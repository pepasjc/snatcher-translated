# saturn/translation - the English data of the Sega Saturn port

`saturn/translation/` holds every piece of English the Saturn build writes into the
game: the scene-bank text (`SAT_NNN_Bxxx.json`), the voice subtitles
(`subs_*.json`), the speaker names, the opening's credit roll and caption,
small picture labels, and the map that ties the Saturn's voice lines to the
PlayStation's. Most of the text was carried over from the PlayStation data in
`ps1/translation/`; the files here are the shipped truth for the Saturn.

String conventions (shared with the PS1 data):

- `￥` (U+FFE5) is a line break inside a string.
- `＠` + a colour kanji switches colour: `＠青` blue, `＠赤` red, `＠紫` purple,
  `＠緑` green, `＠水` cyan, `＠黄` yellow, `＠白` white (back to normal), `＠桃` pink.
  `＠Ｃ` at the end of a line closes the box by itself. A colour code costs 4 bytes.
  `＠緑` text in B030/B040 is Gaudi's terminal (14 cells x 4 rows, no wrap).
- A **cell** is one 16-px character position on screen. English letters are
  packed two to a cell: each letter pair is drawn by a glyph in a kanji slot the
  game no longer uses (the pair table, `work/saturn/pair_table_sat.json`, built
  by `satapply.py` from the PS1's `work/pair_table.json`). A pair with no slot
  falls back to two fullwidth letters (two cells). The dialogue box is 4 rows x
  20 cells.
- **Budget** = the byte length of the original Japanese string including its
  terminating null. An English string costs: each ASCII run between fullwidth
  characters rounded up to an even length (2 bytes per pair, 4 for a pair with
  no glyph slot), 2 bytes per fullwidth character, 4 per colour code, 1 null.
  A string over budget is not shortened: `satlong.py` appends it to the bank
  and remaps the pointer at runtime.
- Typed answers and name-search keys are **fullwidth** Latin (`ＱＵＥＥＮ`): the
  Saturn's keyboard matcher compares one glyph code per typed character.
- `ω` (code 0x7d2a) is a Saturn-only code that ends the verb labels in the
  Japanese (`見るω`); it draws the blank glyph. It is kept where the Japanese
  has it (`Lookω`). What the engine uses it for is not established.

**No Japanese script lives in `saturn/translation/`.** The Japanese stays in the game: the build
extracts `DATA.BIN` from the user's own disc and `satapply.py` overwrites
strings in place, so a string with an empty `en` simply keeps its Japanese.
For review tools, `build.py` dumps the banks to `work/saturn/ref/SAT_NNN_Bxxx.json`
(`satdata.py script`: `{off, budget, jp}` per string, same order as the files
here) and `work/saturn/carry/` (the carry records with the Saturn and PS1
Japanese side by side). The only Japanese in `saturn/translation/`: colour codes inside
English lines, the original speaker names in `names.json` (`jp`), and a few
staff names quoted in `staff_roll.json`'s comment.

## SAT_NNN_Bxxx.json - scene-bank text (39 files)

What it changes: every string of the 39 scene banks (dialogue, menus, verbs,
terminal entries, typed puzzle answers, the name search).

`NNN` is the **DATA.BIN entry number** (the index in the exec's chunk table),
`Bxxx` the PS1 bank it corresponds to: 021 = B000 ... 059 = B260, in the PS1's
order. `SAT_041_B140x` is a small extra bank with no PS1 twin (control records
only); the PS1's B140 text sits in entry 042 together with B150.

- Read at build time by `satapply.py` (`en` into the banks), `satlong.py`
  (`long` and over-budget `en` appended to the bank tail with the remap
  stubs), `satkeys.py apply` (B040's `key`/`initials` records), `satglyphs.py`
  and `satexec.py` (which letter pairs and codes are used).
- Generated by `satcarry.py run` (matches each Saturn string to a PS1 one and
  copies its English). **Running `run` alone overwrites hand edits**: it
  blanks every `carry: new` line and satkeys' records. `build.py` runs
  it only to make the `work/` references and restores the committed files
  afterwards. A real re-carry after PS1 changes is a three-way merge
  (`saturn/CLAUDE.md`, "Carrying the PS1 English"). Edited by hand,
  `satcarry.py terminal --write` (re-flows B030/B040 terminal text at 14
  cells), `satcandidates.py apply` (candidate records) and `satkeys.py fit`
  (B040 keys).

Top level:

| Key | Type | Meaning |
|---|---|---|
| `file` | string | `DATA.BIN[n]`, the chunk the bank is |
| `entry` | int | the DATA.BIN entry number (= `NNN`) |
| `text_base` | int | byte offset of the string region inside the bank (the bank's first BE16 word) |
| `twins` | list of strings | the PS1 banks this chunk was matched against (`["B150", "B140"]` for 042, empty for 041) |
| `strings` | list | one record per null-terminated string, in bank order |

String record:

| Field | Type | Meaning |
|---|---|---|
| `off` | int | byte offset of the string in the bank (also the key the remap uses) |
| `budget` | int | bytes available: the original string's length + 1 null |
| `en` | string | English written in place. Empty = the Japanese stays (control data, locked data, or a key that rides as `long`) |
| `long` | string | optional. Text with no length limit, appended to the bank by `satlong.py`; the engine reads it instead of the slot. Used for full-length lines and labels whose `en` is a short fallback |
| `lock` | bool | optional. The engine reads this string as data (dial table, match patterns); it stays Japanese and `satapply` refuses English there |
| `src` | string | `Bxxx:off` - the PS1 bank and byte offset of the string the English came from |
| `carry` | string | how the record was matched (below); absent on a few unmatched empty records and some B040 key and section-header records |
| `note` | string | free-text remark from the carry or a later pass (`Saturn jp has 1 more break`, `row 1 re-wrapped at 14`, `from B160`, `name-search key: ALICE`...) |
| `en_candidate` | string | the PS1 English offered when the Japanese differs; kept as the record of what was offered, never written by itself |
| `sim` | float | difflib similarity (0-1) between the Saturn and PS1 Japanese, `￥` stripped |
| `key` | bool | B040 only: a name-search key (fullwidth, in `en` if it fits, else in `long`) |
| `initials` | bool | B040 only: a search section header; its fullwidth letters are the first letters routed to that section |

`carry` values:

| Value | Meaning |
|---|---|
| `exact` | Saturn and PS1 Japanese identical; English copied |
| `rebroken` | identical except for `￥` placement; English copied, rows re-wrapped where a row would pass 20 cells (14 on the terminal) |
| `candidate_ok` | Japanese differs; the offered PS1 English was taken as is |
| `candidate_edit` | Japanese differs; the English was adapted by hand (own numbers, fragments, `ω`, rewording) |
| `new` | hand-written: Saturn-only lines (backup-RAM and cartridge messages, B180's phone book, the Saturn's own name-search keys) |
| `lock` | engine data with no PS1 match; stays Japanese |
| `control` | not text: control bytes only; left alone |

Example (`SAT_022_B010.json`):

```jsonc
{
 "off": 10858,          // byte 10858 of DATA.BIN entry 22 (B010)
 "budget": 51,          // the Japanese took 50 bytes + null
 "en": "Only JUNKER personnel may go past￥this point.",   // fits: written in place
 "src": "B010:10722",   // from the PS1's ISZ_B010 string at byte 10722
 "carry": "rebroken",   // same Japanese, different line breaks
 "long": "I'm afraid only JUNKER personnel are￥allowed inside the office.",  // what the player reads
 "note": "Saturn jp has 1 more break"
}
```

A B040 key: `{"off": 4097, "budget": 11, "en": "", "carry": "new", "key": true,
"long": "ＡＳＡＤＥＥ", "note": "name-search key: ASADEE"}` - too long for its
slot, so the fullwidth key rides as a `long`.

## subs_Bxxx.json - voice subtitles per scene (31 files)

What it changes: the subtitle cards shown while a voice line or a stereo reel
plays in that scene. `satsubs.py --all` compiles each file into a blob
appended to the bank's string region, plus the exec stubs that draw it.

- Read at build time by `satsubs.py` (and `satexec.py`, `satglyphs.py` for the
  codes and pairs the rows use).
- Generated by `gen_subs.py <S>|--all` from the PS1 cue file
  `ps1/translation/subs_<S>.json` + `voice_map.json` + `work/master_lines.json`
  + the reel map/alignment in `work/saturn/cat/`; then `bridge_cues.py --write`
  (closes gaps under 1.5 s between cards of one line) and `sat_recut.py --write`
  (re-cuts same-speaker chains into self-contained cards). `gen_subs.py --faces`
  rewrites only `face`, `face_src`, `face_char`.
- **The JSON is the shipped truth.** A full `gen_subs.py` regeneration drops
  hand edits made here (for example `B0C0_013c`, Gillian's sigh, and B1F0's
  motorcycle cards `t_00..t_04` re-timed by ear) and the bridge/recut passes
  must be re-run. Hand edits are recovered by diffing against a regeneration
  from the merge base (`saturn/CLAUDE.md`).

Top level: `scene` (`"B010"`), `options`, `cues`.

`options` (band layout; identical in every bank file):

| Key | Value | Meaning |
|---|---|---|
| `layout` | `"band"` | cards normally drawn in the voice band beside the speaker's portrait |
| `cols`, `rows` | 14, 3 | the band text area the `rows` field was wrapped to (cells x rows); `sat_recut.py` reads them |
| `col0` | 6 | first text column of the band (cells); informational, `satsubs.py` has its own constant |
| `plain_cols`, `plain_rows` | 18, 3 | the wrap `rows_plain` was made with; informational |
| `bytes_per_s` | 11025 | ADPCM bytes decoded per second of a mono voice line; informational |

Cue fields, common to every cue:

| Field | Type | Meaning |
|---|---|---|
| `id` | string | the PS1 cue's id (`B010_000`); suffixes `b`, `x`, `y`... mark cards split from one PS1 cue; unique per file |
| `speaker` | string | English speaker name (as in `names.json`); empty = narration, no nameplate |
| `colour` | int | nameplate colour byte: 1 blue, 2 red, 3 purple, 4 green, 5 cyan, 6 yellow, 7 white (from `names.json`'s `colour`, plus `gen_subs.EXTRA_COLOURS`) |
| `en` | string | the card's full English (the source the rows are wrapped from; not compiled into the blob) |
| `rows` | list of strings | the card wrapped at 14 cells, at most 3 rows. This is what the game draws; with no portrait the payload re-wraps these words at 20 cells at build time |
| `rows_plain` | list of strings | the card wrapped at 18 cells (4 rows with no speaker). Generated but **not used by the payload** since 2026-09-30; `satexec.py` still counts its codes |
| `b0`, `b1` | int | the card shows while the line's byte counter is in `[b0, b1)`. Mono line: ADPCM bytes decoded (11,025 per second). Reel: bytes of the AIFF file played, including its 54-byte header |
| `size` | int | the whole line's size in the same units (the last card of a mono line ends at `size`) |
| `enabled` | bool | false = card not compiled |

Mono voice-line cues (the ACT1/2/3.CAT ADPCM lines) add:

| Field | Type | Meaning |
|---|---|---|
| `line` | int | Saturn voice line number 0-1039 (sound id `0x700 + line`; = `idx` in `voice_map.json`) |
| `act` | int | 1/2/3 = ACT1/2/3.CAT |
| `sector` | int | the line's start sector inside the CAT (2,324-byte units) |
| `offset` | int | byte offset inside that sector; `sector`, `offset`, `act` identify the playing line at runtime |
| `chain` | string | optional: the PS1 anchor cue id of a PS1 "chain" cue (a VAG line with no stream); the Saturn plays it as this ordinary line and the cards split it in proportion |

Stereo-reel cues (cinematics streamed as `SDAIF_nn.AIF`) add:

| Field | Type | Meaning |
|---|---|---|
| `reel` | int | the stream number the engine reports (files numbered in directory order: `SDAIF_E0` = 140) |
| `sdaif` | string | the AIFF file name on the disc |
| `rate` | int | sample rate, Hz |
| `frames` | int | sample frames in the file (`size` = 54 + frames x 4 for 16-bit stereo) |

Portrait fields (optional; the card is drawn face-left only when a portrait is known):

| Field | Type | Meaning |
|---|---|---|
| `face` | [int, int, int] | mono cues: `[slot, buffer, palette]` - the VDP1 portrait slot, the face structure buffer index and the palette byte the room script uses for this speaker |
| `face_src` | `"own"`, `"resident"` or int | where `face` came from: `own` = the room script shows this line on that column; an int = the voice line number of another line in the script that shows the same speaker (the payload copies that column over the hidden one); `resident` = the hand table `gen_subs.RESIDENT_FACES` (B260, Madnar) |
| `face_char` | int | reel cues: the character id (`facechunks.CHARS`: Gillian 1, Mika 2, Chief 3, Harry 4, Metal Gear 5, Catherine 6, Randam 7, Teller 8, Madnar 9, Ivan 10, Napoleon 11, Chin 12, Jamie 13, Cook 14, Woman 15); the payload finds the column by the portrait's pixels |

Mono cues with no `face` whose speaker has a character id are still checked by
portrait content at runtime. Examples (`subs_B010.json`):

```jsonc
{"id": "B010_000", "line": 198, "act": 1, "sector": 3715, "offset": 1278,
 "size": 33233, "b0": 0, "b1": 33233,          // the whole line: 33,233 ADPCM bytes, ~3 s
 "speaker": "Gillian", "colour": 4,            // green nameplate
 "en": "I'm Gillian Seed. I've been assigned to JUNKER as of today.",
 "rows": ["I'm Gillian Seed. I've been", "assigned to JUNKER as of", "today."],
 "rows_plain": ["I'm Gillian Seed. I've been assigned", "to JUNKER as of today."],
 "enabled": true, "face": [4, 4, 4], "face_src": "own"}   // her column as the script sets it

{"id": "B010_f5_0", "reel": 135, "sdaif": "SDAIF_D5.AIF", "rate": 30000,
 "frames": 1960113, "b0": 171566, "b1": 719286, "size": 3920280,   // file bytes 171,566..719,286
 "speaker": "Harry", "colour": 5, "en": "I know. Shall we call the Navigator ...",
 "rows": [...], "rows_plain": [...], "enabled": true, "face_char": 4}   // Harry's portrait
```

## subs_INTRO.json - the opening's subtitles

What it changes: the 24 narration cards over the opening (newsreel and
Gillian's profile), shown from the title screen to the first scene. The opening
has no bank of its own, so the blob rides in B000 (entry 21).

- Read by `satsubs.py` (`--all` includes it); the harness `intro_run.py`.
- Generated entirely by `gen_intro.py` from `ps1/translation/subs_INTRO.json`
  (English and card splits verbatim) and measurements in `work/saturn/`.
  Regeneration rewrites the whole file; no hand edits are known to live in it.

`options`:

| Key | Value | Meaning |
|---|---|---|
| `layout` | `"plain"` | the plain box, no portrait, no nameplate |
| `cols`, `rows`, `row0` | 20, 3, 0 | up to 3 rows of 20 cells starting at box row 0 |
| `cue_y` | true | each cue carries its own box position (`y`) |
| `linger` | 120 | frames the box stays open waiting for the next card |
| `prio` | 31 | sprite draw priority of the box while a card is up (the boards' sprites run at 30/31) |
| `frame` | false | no gold box frame; only the dark fill behind the rows |
| `slide` | 128 | box slide step in pixels per frame (128 = appears in one frame) |
| `lag_s` | 0.167 | seconds the stream counter runs ahead of the audio; already added into `b0`/`b1`; informational |
| `bank`, `chunk`, `scene_var` | `"B000"`, 21, 0 | the bank the blob rides in; informational (`satsubs.SCENES` decides) |
| `timing` | string | how the windows were derived; informational |
| `align` | object | per SDAIF file: `ps1` (the PS1 stream), `a`, `b` (Saturn time = a x PS1 time + b), `corr` (envelope correlation); informational |

Cues use the reel fields above (`reel`, `sdaif`, `rate`, `frames`, `b0`, `b1`,
`size`, `speaker` empty, `colour` 7, `en`, `rows`, `enabled`; no `rows_plain`)
plus:

| Field | Type | Meaning |
|---|---|---|
| `t0`, `t1` | float | card window in seconds into the Saturn reel, before `lag_s` (informational) |
| `y` | int | pixels the box sits below its home position; row 0 starts at screen line 158 + `y`. Compiled into the cue |
| `pic_bottom` | int | lowest non-black screen line of the picture over the card's span (from `intro_run.py --measure`) |
| `over` | bool | true = the rows could not clear the picture and still cross it (the full-screen boards) |

Example: `{"id": "INTRO_news_00", "reel": 140, "sdaif": "SDAIF_E0.AIF", ...,
"t0": 35.9, "t1": 43.8, "b0": 4327822, "b1": 5276114, ..., "pic_bottom": 177,
"y": 23, "over": false}` - the picture ends at line 177, so the rows start at
158 + 23 = 181, 3 px below it.

## names.json - speaker names

What it changes: the 78 speaker names in the exec's name table (the nameplate
of ordinary script dialogue). Also gives each subtitle speaker its nameplate
colour.

- Read by `satnames.py apply` (writes the names into `MAIN_L.BIN`, keeping each
  original `＠colour ... ＠白` wrapper byte for byte from the pristine exec),
  `gen_subs.py` (colours), `satexec.py` (used codes), the harness.
- Edited by hand.

Top level: `note` (description), `names` (list of 78, in table order).

| Field | Type | Meaning |
|---|---|---|
| `index` | int | position in the name table (0-77; must equal the list position) |
| `jp` | string | the original name without its colour wrapper (reference) |
| `colour` | string | the colour kanji of the original wrapper (`青` blue, `赤` red, `紫` purple, `緑` green, `水` cyan, `黄` yellow, `白` white) |
| `reset` | bool | the original ends with `＠白`; reference only, the wrapper is rebuilt from the exec |
| `en` | string | English name drawn on the plate (pair-encoded; widest name 6 cells) |
| `src` | string | `ps1` = the PS1's name list (`ps1/tools/translate_names.NAMES`); `saturn` = romanised here (the Tokimeki Memorial cast and Konami staff in B100) |
| `note` | string | optional remark |

Example: `{"index": 0, "jp": "メタルギア", "colour": "青", "reset": true, "en": "Metal Gear", "src": "ps1"}`.

## staff_roll.json - opening credit roll and caption

What it changes: the cast/staff roll after New Game (including "2042.12 / NEO
KOBE CITY") and the "KONAMI OMNI BLDG / JUNKER HQ" caption typed under the
tower. Both are sprite pictures; `satroll.py apply` redraws them into chunks
394 (roll) and 452 (caption) from pristine on every build.

- Read by `satroll.py`; edited by hand.

| Key | Type | Meaning |
|---|---|---|
| `_comment` | string | description and the readings chosen for some staff names |
| `screens` | list | one entry per roll screen, in play order |
| `screens[].list` | int | the sprite list in chunk 394 (1-23) that screen draws; the play order runs ..17, 19, 20, 18, 21.. |
| `screens[].lines` | list of strings | the screen's text lines, top to bottom; the count must match the original's text rows. Two or more spaces inside a line split it into columns |
| `caption` | [string, string] | line 1 replaces コナミオムニビル; line 2 is the text after the original JUNKER (replaces 本部) |

Example: `{"list": 14, "lines": ["GRAPHICS", "Junko Koike    Mihoko Kimura"]}` -
the second line is drawn as two columns.

## gfx_labels.json - small labels inside pictures

What it changes: Japanese text painted into a few sprite pictures: the
videophone NOT IN SERVICE / NO VIDEO cards (237, 238), the note among the item
close-ups (361-366), the JUNKER poster (489) and the B180 phone-book jokes (250,
252, 253, 261).

- Read by `satlabels.py apply` (in the build chain; writes decoded chunk
  overrides to `patched/saturn/chunks/NNN.bin`, which `satpack.py` packs).
  `satlabels.py preview` draws before/after PNGs in `work/saturn/labels/`.
- Edited by hand. Edits always start from the pristine picture.

Top level: `_doc` (description) and one entry per picture, keyed
`<chunk>_<name>`; keys starting with `_` are skipped. Several entries may edit
the same chunk (`252_not_home`, `252_option_menu`).

| Field | Type | Meaning |
|---|---|---|
| `chunk` | int | DATA.BIN entry holding the picture |
| `list` | int | the sprite list in that chunk; its pieces are composed into one canvas (top-left piece at 0,0) |
| `palette` | int | optional: palette used for the preview (default: from the list's CLUT) |
| `store` | list of int | optional: write back only these records of the list (pieces overlapping other art) |
| `_note` | string | optional remark |
| `edits` | list | operations applied in order, in canvas pixels and palette indices |

Edit operations (one per object; coordinates are inclusive rectangles `[x0, y0, x1, y1]`):

| Operation | Fields | Effect |
|---|---|---|
| erase | `erase`, `fill` | fill the rectangle with index `fill` |
| move | `move`, `dx`, `dy`, `fill` | shift a rectangle, filling the hole |
| copy | `copy`, `to`, `source` (`"original"`), `only` | copy pixels (optionally only some indices, optionally from the unedited picture) |
| remap | `remap`, `map` | replace indices inside the rectangle (`{"5": 18}`) |
| inpaint | `inpaint`, `values` | each listed index takes the commonest surrounding other index |
| pixels | `pixels` (rows of `#`/`.`), `x` or `span`, `y`, `ink`, `drop` | hand-set lettering; `drop` = shadow index one row below |
| text | `text`, `y`, `x` or `span`, `ink`, `shadow`, `outline`, `font` (`6x13`, `5x7`...), `scale` | render text in a bitmap font; `y` is the top of the font cell, `span` = [x0, x1] for centring and overrun checks; `shadow` at +1,+1 |

Example (`237_not_in_service`, list 12): erase `[5, 10, 144, 23]` with index
210, then draw `"Number not in use."` at y 11 centred in x 5-144, ink 255,
shadow 65.

## voice_map.json - Saturn voice lines to PS1 streams

What it is: a list of 1,040 records pairing each Saturn voice line (ACT1/2/3.CAT,
IMA ADPCM) with the PS1 mono XA stream that holds the same recording. It
changes nothing in the game by itself; `gen_subs.py` uses it to re-time the
PS1's subtitle cues onto Saturn lines.

- Read by `gen_subs.py` (not by the build).
- Generated by `satcat.py match <PS1 work dir>` (envelope correlation of every
  line against the PS1 census) into `work/saturn/voice_map.json`, then copied
  here. No hand edits.

| Field | Type | Meaning |
|---|---|---|
| `idx` | int | Saturn line number 0-1039 (sound id `0x700 + idx`; the cues' `line`) |
| `act` | int | 1/2/3 = ACT1/2/3.CAT (ACT1 0-254, ACT2 255-625, ACT3 626-1039) |
| `sector` | int | start sector inside the CAT (2,324-byte units), from the exec's voice table |
| `offset` | int | byte offset inside that sector |
| `size` | int | ADPCM bytes of the line (11,025 per second) |
| `ps1` | string | the PS1 stream key in `work/master_lines.json` (`XAS_M000.XA[24]`) |
| `file`, `chan` | int | that stream's XA file number and channel (what the PS1 cue files key on) |
| `corr` | float | envelope correlation of the match (1,037 above 0.95) |

Example: `{"idx": 1, "act": 1, "sector": 15, "offset": 1978, "size": 31417,
"ps1": "XAS_M000.XA[24]", "file": 2, "chan": 0, "corr": 0.9999}` - Saturn line 1
starts at byte 1,978 of sector 15 of ACT1.CAT, lasts 31,417 bytes (~2.8 s),
and is the PS1's stream 24 (file 2, channel 0).
